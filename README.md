# 「しらんけど」完全自動トレンドサイトシステム 基本設計書 (Master Specification)

## 1. システム全体構成 (System Architecture)

「しらんけど」は、単なるまとめサイトや無秩序なAI量産ブログではなく、**「話題発見」「情報確認」「安全判定」「AI要約生成」「独自指標付与」「マルチチャネル配信」**を明確に分離した高信頼トレンドメディアシステムです。

### 処理パイプライン
```
[トレンド取得元]
 ├ Googleトレンド (検索需要)
 ├ Yahoo!リアルタイム (SNS爆発力)
 ├ YouTube API (動画カルチャー)
 ├ ニュースランキング (閲覧需要)
 └ ゲームランキング (Steam/新作/アプデ)
         │
         ▼ (話題発見 Discovery)
[重複統合 & 正規化エンジン]
   ・同義語・固有名詞・時間枠による名寄せ
         │
         ▼
[しらんけど指数 算出 (0〜100点)]
   ・情報源ごとの重み付け ＋ 急上昇率(+%判定) ＋ 初出時刻記録
         │
         ▼
[信頼できる情報源 (公式・報道) 事実確認]
   ・公式発表、企業リリース、大手報道の一次ソース突合
         │
         ▼
[安全判定エンジン (Safety Brake)]
   ・危険ジャンル (犯罪・訃報・病気・不倫・金銭・一般人) を検知
   ・疑わしい/一次情報不足 → 自動「保留 (Hold)」へブレーキ
         │
   [安全確認済]
         ▼
[AI記事生成エンジン (Gemini / マルチプロバイダー)]
   ・確証情報のみを構造化要約
   ・本文末尾を自然な「〜しらんけど。」で締結
   ・出典一覧 (一次ソースリンク) 自動付与
         │
         ▼
[インテリジェント画像マッチング (10,000枚規模)]
   ・専用画像 ＞ グループ画像 ＞ カテゴリ汎用 ＞ サイト共通
   ・使用履歴・最終使用日時の平準化
         │
         ▼
[自動公開 & SNSキュー登録]
   ├ フロントエンド即時反映 (PC/スマホレスポンシブ)
   └ X / Pinterest / Instagram 各サービス別テンプレートで時差配信
         │
         ▼
[ユーザー参加]
   ├ 匿名2択投票 (知ってた/知らんかった、もっと伸びる/もう終わる)
   └ テキスト限定コメント (URL拒否・拒否ワード自動遮断)
```

## 2. DB設計 (Database Schema & Indexes)

MySQL 8.0 / MariaDB 10.5+ を前提とし、すべてのテーブルに `site_id` を配置してマルチテナント完全分離を実現します。大容量(10,000枚画像、数万件トレンド・記事)に耐える適切な複合インデックスを設定。

### 主要テーブル一覧
1. `sites` (サイト基本設定・サブドメイン・公開設定)
2. `categories` (サイト別カテゴリ)
3. `trend_candidates` (取得トレンド候補・重み・急上昇度)
4. `articles` (生成記事・ステータス・しらんけど指数・末尾文)
5. `article_sources` (記事の出典・参考一次情報)
6. `images` (画像ライブラリ・利用回数・最終利用日時)
7. `image_groups` (人物・作品・ゲームグループ)
8. `image_keywords` (画像キーワードマッピング)
9. `user_votes` (投票データ・IPハッシュ・集計)
10. `comments` (テキスト限定コメント・ステータス)
11. `banned_keywords` (拒否キーワード・判定種別)
12. `sns_queue` (SNS予約配信キュー・成否ログ)
13. `site_settings` (AI設定、指数配点、SNSキー、安全設定等のKey-Value)
14. `system_logs` (動作ログ・エラーログ・管理者操作ログ)
15. `migrations` (自動マイグレーション履歴)

## 4. マルチサイト構成 (Multi-Site & Wildcard Subdomain)

### 動作原理
1. サーバーのDNSに `*.example.com` (Aレコード) を設定。
2. Apache/NginxのServerAlias `*.example.com` を同一ドキュメントルートに向ける。
3. リクエスト時に `$_SERVER['HTTP_HOST']` を解析:
   - `game.example.com` → subdomain: `game` → `SELECT * FROM sites WHERE subdomain = 'game'`
   - `example.com` (または設定された親ドメイン) → `subdomain = ''` または default `site_id = 1`
4. 該当する `site_id` が確定後、全SQLクエリに `WHERE site_id = ?` を自動バインド。
5. 管理画面の「サイト切替」により、同一管理画面からどのサイトのデータも瞬時に俯瞰・操作可能。

## 5. トレンド取得設計 (Trend Aggregation Engine)

1. **Googleトレンド (RSS / API)**
   - 目的: 実際に検索ボリュームが急上昇しているキーワードと前日比の上昇率。
2. **Yahoo!リアルタイム検索 (急上昇・話題ワード)**
   - 目的: SNS上で今まさに爆発しているホットワードの**「発見」のみ**に使用（事実認定には一切使わない）。
3. **YouTube Data API / 急上昇ランキング**
   - 目的: 動画プラットフォーム発のトレンド、動画ID、サムネイル、公式チャンネル。
4. **ニュースランキング (主要ポータルRSS / 公開API)**
   - 目的: 「読まれているニュース」の一次報道タイトル・報道機関。
5. **ゲーム系ランキング (Steam Top Sellers / ストアAPI / 新作リリース情報)**
   - 目的: ゲーム特化サブサイト（`game.example.com`）向けのアップデート・販売動向。
6. **重複統合 & 正規化**
   - 同一キーワード（「千鳥」「大悟」「千鳥 大悟」等）や同一URLを正規化して同一トピックIDに統合。

## 6. AI処理設計 (AI Provider Abstraction & Prompts)

### プロバイダー抽象化
`AiProviderInterface` を定義し、`GeminiProvider` (デフォルト: `@google/genai` gemini-3.8-flash) と `OpenAiProvider` を交換可能に。

### AI生成厳密ルール
- **Fact-only Constraint**: 与えられた公式発表・報道機関サマリー以外の推測・噂は1文字も追加しない。
- **No Criminal Slander**: 容疑段階の人物を犯人扱いせず、一般人の個人情報は完全にマスキング。
- **Natural Conclusion**: 記事本文の最終パラグラフは、文脈に沿った自然な言い回しで**「〜しらんけど。」**で終了させる。
  - 例: 「大型アップデートの全容は明日の公式配信で明かされる見通しです。しらんけど。」
- **出典リンク明記**: 記事下部に「参考・出典」として一次情報源をリストアップ。

## 7. 安全判定フロー (Safety Brake System)

1. **危険キーワード辞書検知**:
   - `犯罪`, `逮捕`, `容疑`, `不倫`, `離婚`, `薬物`, `病気`, `訃報`, `死亡`, `自殺`, `事故`, `事故責任`, `金銭トラブル`, `未成年`, `一般人`
2. **情報源信頼度スコアリング**:
   - 公式サイト/公式発表 = 信頼度 100
   - 主要全国紙・通信社 = 信頼度 90
   - SNSのみ = 信頼度 20 (記事化基準未満)
3. **判定分岐**:
   - 危険キーワードが含まれる OR 信頼度スコア < 80 → **自動「保留 (HOLD)」**に落とし、管理画面の「危険・保留記事」へ隔離。
   - 管理者が目視確認して「承認」を押すまで一般フロントエンドには一切公開しない。

## 8. 画像選択設計 (10,000 Scale Image Management)

1. **管理者が登録する著作権確認済みの画像ライブラリのみ使用** (スクレイピング等による無断保存は行わない)。
2. **優先度カスケード**:
   1. 記事重要キーワードに完全合致する人物・作品・ゲーム専用画像
   2. 関連グループ（例: 「千鳥」グループ）内の画像
   3. カテゴリ汎用画像（エンタメ汎用、ゲーム汎用など）
   4. サイト共通デフォルト画像
3. **連続使用防止アルゴリズム**:
   - 画像テーブルに `use_count` (使用回数) と `last_used_at` (最終使用日時) を保持。
   - スコア = `(現在時刻 - last_used_at) / (use_count + 1) * RAND()` で重み付けし、直近使用画像を避けつつ適度なランダム性を維持。
4. **YouTubeサムネイル**:
   - サイト設定で「YouTubeサムネイルを使用: ON」の場合のみ埋め込みサムネイルを適用。

## 9. ユーザー投稿・参加設計 (User Interaction & Anti-Spam)

1. **投票機能**:
   - 「知ってた / 知らんかった」 (二者択一・%即時再計算)
   - 「もっと伸びる / もう終わる」 (二者択一・%即時再計算)
   - クッキー ＋ IPハッシュ（ソルト付きSHA-256）で短時間の多重投票を防止。
2. **コメント機能**:
   - **文字のみ (Plain Text Only)**。画像、動画、HTML、URLは一切禁止。
   - URL検知 ( `http://`, `https://`, `www.`, `dot com`, 短縮URL等) を全件ブロック。
   - 拒否キーワード (誹謗中傷、脅迫、差別、個人情報) を完全一致・部分一致・正規表現で照合し即時拒絶。
   - すべての投稿欄付近とフッターに「誹謗中傷禁止・コメント利用ルール」へのリンクを常時掲出。

## 10. SNS投稿設計 (SNS Queue & Templates)

1. **非同期キュー方式**:
   - 記事公開時に `sns_queue` テーブルへエンキュー。記事公開レスポンスをブロックしない。
2. **媒体別最適化テンプレート**:
   - **X**: 魅力的な短い要約 ＋ 記事URL ＋ アイキャッチ画像
   - **Pinterest**: アイキャッチ画像 ＋ タイトル ＋ 詳細解説文 ＋ 記事URL
   - **Instagram**: 高品質画像 ＋ 自然な解説ストーリー ＋ 厳選ハッシュタグ
3. **レート制限・時間差投稿**:
   - 1日の最大投稿数、投稿インターバル（例: 最低30分間隔）を遵守しスパム判定を防止。

1. **ダッシュボード**: 今日の取得トレンド数、記事化数、自動公開、保留数、SNS成功/エラー、コメント数、サイト切替

5. **カテゴリ管理**: サイト別カテゴリCRUD
6. **しらんけど指数設定**: ソース別配点スライダー(計100点)、ラベル編集、急上昇判定閾値
7. **AI設定**: APIキー、モデル選択(gemini-3.8-flash等)、文字数、温度、システムプロンプト
8. **情報源設定**: 収集元ON/OFF、更新頻度、取得上限
9. **画像管理**: 1万枚対応ページング、タグ付与、一括アップロード、使用統計
10. **画像グループ管理**: 人物・作品・ゲームグループの作成とキーワード紐付け
11. **コメント管理**: コメント一覧、承認・非表示・削除、IP通報
12. **拒否キーワード**: 判定ルール(完全/部分/正規表現)、有効無効切替
13. **ユーザー投票**: 投票ログ集計とリセット
14. **SNS設定**: X/Pinterest/Instagram APIキー、自動投稿ON/OFF、テンプレート設定
15. **SNS投稿履歴**: キュー実行状況、再試行、エラーログ
16. **危険記事・保留記事**: ブレーキがかかった記事の緊急レビュー、解除/破棄
17. **固定ページ**: 「しらんけど指数とは？」「利用ルール」等の編集
18. **SEO設定**: OGP、Twitter Card、メタタグ、sitemap、robots.txt
19. **システム設定**: 疑似cron/手動実行トリガー、データエクスポート
20. **ログ**: トレンド収集、AI API、SNS配信、管理者操作の詳細ログ

## 12. フロントエンド構成 (Frontend Architecture)

- **トレンドニュース専用の洗練されたUI**:
  - スマートフォンファーストの快適なスクロールと軽快なレスポンシブデザイン。
  - トレンドバッジ、しらんけど指数ゲージ、急上昇「🔥 +145%」インジケーター。
  - 「話題発生から2時間」「話題継続3日目」等の経過時間表示。
  - 記事末尾の「〜しらんけど。」のユーモアと、真面目で信頼性の高い事実要約の調和。
